Definitions

Gradle files

Kotlin variable Groovy variable Definition
minSdk minSdkVersion The minimum SDK version your app will support, defined in build.gradle. For example, if your minSdk is 26, this SDK version corresponds to API level 26 and Android 8, so your app will only run on devices with Android 8 or higher.
targetSdk targetSdkVersion The SDK version that your app targets, defined in build.gradle. It's usually the same as compileSdk, and shouldn't be higher.
compileSdk compileSdkVersion The SDK version that your app compiles against, defined in build.gradle. Android Studio uses this SDK version to build your AABs and APKs. It's usually the same as targetSdk, but it can be higher, for example to use newer APIs before targeting a newer level.

Code files

Variable Definition
Build.VERSION.SDK_INT The major API level of the Android OS currently running on the user's device. For example, on a device running Android 11, this value will be 30 (aka Build.VERSION_CODES.R), even if the target and compile SDK of the app is different. Minor SDK releases retain their integer major API level.
Build.VERSION.SDK_INT_FULL The full API level of the Android OS, including its minor API level. For example, Android 17 QPR1 is API level 37.1 and reports 3700001 (aka Build.VERSION_CODES_FULL.CINNAMON_BUN_1), while SDK_INT remains 37. Possible values are defined in Build.VERSION_CODES_FULL.

Footnotes

  1. Cumulative usage distribution figures were last updated on November 03, 2026 using October 2026 data from Statcounter GlobalStats and this script. These figures may have changed significantly since the last update. You may update the figures yourself with a pull request. ↩

  2. The codenames for Android 10 and above in the table are the internal codenames. Beginning with Android 10, Google dropped the usage of codenames publicly. ↩

  3. Android 4.4W is the first Android release for Android Wear. ↩

  4. The years represent the year of first stable release of each version. The release dates are from android.os.Build.VERSION_CODES including later versions' years from the Official Android blog (12, 12L, 13, 14, 15, 16, 17) ↩

  5. Existing apps that target a lower API level are no longer available to new users on devices running an Android version higher than the app's targetSdk. For example, new users can still install an app targeting API level 34 on Android 14 and lower, but not on Android 15 or higher. ↩

  6. Minor releases have no constant in Build.VERSION_CODES. Their constants are only in Build.VERSION_CODES_FULL, where values encode both the major and minor API level, for example 3600001 for API level 36.1. ↩
