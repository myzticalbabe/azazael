## Interface you publish (frozen at the end of step 1)

- `SarahProfile` — eight float axes in `0..1`: `processing_speed`, `wm_span`,
  `sustained_attention`, `sensory_gain`, `interoceptive_accuracy`, `time_discrimination`,
  `initiation_threshold`, `recovery_latency`. Each axis carries its `source`
  (`"user" | "probe" | "telemetry"`); plus `version`, `to_dict()`, `from_dict()`.
- **Precedence: user > probe > telemetry.** Telemetry may never write a diagnosis field, and
  there is no diagnosis field to write.
- `ProfileStore` — versioned records in pmb; inspectable; deletable in one call.
- `Preview` — `{what, duration_s, how_to_leave}` returned *before* any state change.
- `ExitPort` — `leave()` returns to the low-stimulation hub; `resume()` restores state via pmb.

Lanes 2 and 3 consume `SarahProfile` read-only. Changing a field name after the freeze is a
breaking change and must be announced in the handoff, not slipped in.

## Execution model — LLM workers and xdist

**Workers.** This lane is executed by LLM workers, one per module, because the allowlist
partitions cleanly by file. The only serialisation point is the interface freeze: step 1
publishes `docs/SARAH_INTERFACE_2026-11-16.md`, and the M6/M7/M10/M11 workers may start in
parallel the moment it lands. Lanes 2 and 3 do not wait for this lane to *finish* — only for the
contract.

**xdist is per-environment, measured 2026-11-16.** `-n auto` is opt-in and is **not** in the
committed addopts, because a committed flag one interpreter cannot parse kills the run at
argument parsing — before collection, so nothing is reported at all (not a skip, not a failure):

| interpreter | xdist | how to run tests here |
| --- | --- | --- |
| `py316t` (production) | **3.8.0** — installed 2026-11-16 (execnet 2.1.2) | `-m pytest ... -q -n auto` (16 cpus) |
| `py315t` (GIL sidecar) | **3.8.0**, pytest 9.2.0 | `-m pytest ... -q -n auto` |
| bare `python` on PATH (3.14.7) | absent | `-m pytest ... -q`, **never** with `-n` |

Both production and the sidecar now run in parallel, so the acceptance commands below may use
`-n auto` wherever they name py316t. `-n` stays out of the committed addopts because bare
`python` on PATH is 3.14.7 with no xdist and still reads this file. A command that dies on an
unrecognised `-n` is a wrong command, not a red suite.

**Proven on py316t 2026-11-16** (`pytest-xdist 3.8.0`, `execnet 2.1.2`): `pytest tests -q --co -n 2`
collected 7,719 tests (RC=0, 10.16 s); `pytest tests/test_calc.py tests/test_qd_alert_weight.py
-v -n 2` reported `[gw0]`/`[gw1]` interleaved and `6 passed in 1.46s` (RC=0); `-n auto` resolved to
16 workers and ran `2 passed in 2.73s` (RC=0). A flag that parses is not a worker that runs, so
the `[gw0]`/`[gw1]` pair is the evidence this row rests on.

## Evidence constraints

- The eight axes are **instruments, not claims**. No axis may be labelled with a diagnosis.
- M11 body doubling is optional and labelled *self-report, no RCT* — a 2025 ASSETS EEG study
  found no significant effect.
- PDA is a contested construct (Kildahl 2021; JADD 2026), so autonomy-preserving interaction
  (invitation, choice, no imperative verb) is the default **for every user** and is never gated
  on a diagnosis. It costs nothing when the construct is wrong.
