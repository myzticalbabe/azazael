## 2. Files that must NOT be blindly rewritten

A global find-and-replace will break these, and in two cases will destroy a record:

1. **`MASTER_CAPABILITY_TODO.md:171`** — the string is a *description of the defect*.
   Deleting it erases the item that tracks the work. Rewrite the example to `<user>`
   and keep the item text.
2. **`Project_FLAMING_SWORD/config.example.json`** — the file carries a `note` field
   that explains *why* the path is absolute ("the sweep may run under a different
   interpreter than the ledger expects"). A silent substitution leaves the note
   justifying something that is no longer true. Re-word, don't replace.
3. **`Project_FLAMING_SWORD/tests/test_sword.py:225-226,244`** — absolute paths are
   deliberate fixtures for the `two-interpreters` detector. Confirmed by the
   FLAMING SWORD auditor; replacing them disarms the test.
4. **`Project_SHARDEX/tests/test_shardex.py:29-31`** — Chrome-path fixtures, same class.
5. **`logs/` and generated reports** — regenerable. Delete or regenerate rather than
   rewriting, or the next run restores the paths.

**Sanitization approach that would work:** replace both `C:/Users/clint` and
`C:\Users\clint` with a single documented placeholder — `<HOME>`, or an env var such as
`$AZAZAEL_HOME` — and state the convention once in CONTRIBUTING. Handling both
separators matters: the tree is Windows-native and both forms are in use.
