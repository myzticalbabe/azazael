# AUDIT — committed secrets and credentials (2026-11-02)

**Scope:** `C:/Azazael/azazael`, prepared for public GitHub publication.
**Auditor:** 11 of 18, full-audit fan-out. **READ-ONLY** — nothing in this tree was modified.
**Verdict: no real credential found. Publication is not blocked by this audit on any file I read.**

---

## 1. Method, and why the method matters

`glob` and `code_search` are unreliable in parts of this tree: they return
`Found 0 matches` with exit code 2 when scoped to the home directory, and `glob`
silently skips directories such as `.github/`. A zero from either is therefore
**not evidence of absence** — a control search for `Project_CRADLE`, a directory
that verifiably exists, also returned 0 under that scope.

What worked: `code_search` **scoped to a repo subdirectory** returns exit 0 and
real results. Every search below was scoped to `C:/Azazael/azazael` or
`C:/Azazael/azazael/config`, and every hit was confirmed by `read_files` rather
than trusted from the search alone.

## 7. Not checked — named so absence is not read as a pass

- **No git access.** I could not run `git ls-files`, `git log -p`, or history
  secret-scanning. A secret added and later deleted is invisible to every method
  used here. Owed: `gitleaks detect --source . --redact` over full history, and
  `git ls-files | grep -E '\.env$|\.pem$|\.p12$|\.key$'`.
- **`src/CORE/inference/providers.py` and other provider modules** were not read.
  `.env.example` shows they read keys from the environment, which is correct
  practice, but I did not verify no module carries a hardcoded fallback default.
- **Jupyter notebooks, `.yml`/`.toml` files outside `config/`**, and
  `packages/azazael-core/**` were not read.
- **Board store, PMB/Engram databases, and `memory_store.db`** were not examined.
  They are not publish candidates, but if any is ever tracked they are a far
  larger leak surface than any source file.
- Binary files (`.exe`, `.pyc`, images) cannot be searched by these tools at all.

---

## 8. Recommendation

Publication is **not blocked** by this audit. Before the first public push, run
these three, each of which covers a gap above:

1. `gitleaks detect --source . --redact` over full history — the only check that
   sees deleted secrets.
2. `git ls-files | grep -E '\.env$|\.pem$|\.p12$|\.key$|credential'` — proves no
   credential file is tracked, including historically-ignored ones.
3. Re-run `python tools/twelve_factor_audit.py --check` on the exact tree being
   published, since its detector already covers the common prefixes.

All three are cheap, and none of them can be satisfied by the read-only pass I
was able to perform.
