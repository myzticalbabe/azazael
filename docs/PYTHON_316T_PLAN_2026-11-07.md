## 2. Microcode Adaptiveness

**Objective:** Dynamically detect and adapt to CPU microcode revisions, enabling runtime selection of optimized code paths based on microcode capabilities (AVX-512, AMX, AVX-VNNI, etc.).

### 2.1 Current State
- CPU: Intel Arc 140T (Xe LPG, 8GB, 128 EU)
- Microcode: Loaded via Windows Update / Intel driver
- No runtime microcode detection in tree

### 2.2 Required Capabilities
| Capability | Verification | Status |
|------------|--------------|--------|
| CPUID leaf 0x07/0x0D read | Parse `AVX512F`, `AVX512VNNI`, `AMX-BF16`, `AMX-INT8`, `AMX-TILE` | ⬜ |
| Microcode revision read | `IA32_MCU_REVISION` MSR (0x8B) via `rdmsr` or kernel driver | ⬜ |
| Dynamic dispatch | Function multiversioning based on detected features | ⬜ |
| Fallback paths | Scalar/AVX2 fallback when microcode lacks feature | ⬜ |

### 2.3 Implementation Approach
1. **CPUID probe module** (`CORE/cpuid.py`): Read `cpuid` via `ctypes` + inline asm or `/proc/cpuinfo` equivalent on Windows (`GetLogicalProcessorInformationEx`)
2. **MSR reader**: Use `winring0` / `msr` kernel driver or `kernel32.DeviceIoControl` with `IOCTL_RDMSR`
3. **Dispatch table**: `CORE/microcode_dispatch.py` mapping feature flags → optimized kernels
4. **Integration**: Hook into `CORE/freethreading.FreeThreadPool` worker initialization

## 4. Language Evolution

**Objective:** Leverage 3.16-only language features: `sys._is_gil_enabled()`, `Py_GIL_DISABLED` config var, free-threading C-API (`Py_BEGIN_CRITICAL_SECTION` / `Py_END_CRITICAL_SECTION`), per-interpreter GIL, JIT hooks (PEP 744), and `typing` extensions.

### 4.1 Current State
- `sys._is_gil_enabled()`: Available, returns `False`
- `Py_GIL_DISABLED`: Available via `sysconfig`, returns `1`
- Free-threading C-API: Not yet used in tree
- PEP 744 (JIT hooks): Not yet implemented in 3.16a1
- `typing` 3.16 features: `TypeIs`, `read_only` params, `Unpack` improvements
