# Kernel map — what has to be portable, and why

**Status:** `requiem` built and propagated (2026-11-02). The rest specified with
acceptance tests, not yet built. "Kernel" here has one meaning: **a single file
that travels with a codebase, runs on the standard library, and needs no
installation** — because a codebase that must install another codebase to record
its own crash, or audit its own tree, will do neither.

---

## 1. `requiem` — a dying last scream (BUILT)

`src/PSYCHE/requiem.py`, copied to 12 codebase roots as `requiem.py` by
`tools/requiem_propagate.py`, byte-identical and drift-checked.

```python
import requiem
requiem.scream()            # sys.excepthook + threading.excepthook + faulthandler
```

| property | value | why |
| --- | --- | --- |
| grave | `<codebase>/.requiem/requiem.jsonl` | accountability travels with the repo |
| raises | never | a recorder that throws loses the first failure |
| changes outcome | never | chains to the hook it replaced; exit status preserved |
| names a cause | never | cause is a judgement made at the worst moment |
| fatal signals | `.requiem/fatal.txt` via `faulthandler` | SIGSEGV cannot run Python |

Proven in a foreign codebase (`azazael-forensics`): exit `1`, traceback still
printed, one record with `recorded: true`, grave local to that repo. 15 controls,
including a real subprocess death.

**What it is not:** it records the death of a process. It knows nothing about a
swallowed exception that never killed anything — that is kernel 5.

## 2. `receipt` — provenance for any artefact

The estate already behaves this way by convention (`FETCH_LOG.md`,
`{"raw","sha","sha_source","url","fetched","tier"}` in the BCC trees) and has no
portable implementation of it, so each tree re-invents the fields slightly
differently and the differences only surface when someone tries to verify.

Kernel: `receipt(artifact_path, *, source=None, tier=None, note=None)` → one row:
`sha256`, bytes, `fetched_at` (UTC), `source`, `tier`, `raw_path`, and the row's
own hash of the previous row (kernel 4 supplies the chain). Refuses a tier it
cannot justify: `A` needs a primary document path, `B` an official index URL.

Acceptance: a re-fetch that returns different bytes must produce a `conflict`
row, not a quiet overwrite; a row missing `sha` must be refused at write time.

## 3. `astaudit` — the code half of a forensic audit

A single pass over a tree that emits **evidence rows**, not a report:

- per file: `path`, `sha256`, lines, language, parse status
- symbols: classes, functions, decorators, `__all__`, entry points
- coupling: imports (module + names), inbound/outbound per module
- **swallow sites**: every `except` with a single-statement body, the exact shape
  the commit gate already blocks — the audit should be able to say how many a tree
  carries *without* git
- **secret-shaped literals**: high-entropy strings, `AKIA…`, private-key headers,
  bearer tokens — flagged, never printed in full
- **claims**: `TODO`/`FIXME`/`HACK` with file:line, so a spec's promises can be
  counted rather than remembered
- **dead public surface**: public functions with no inbound reference in-tree

Every row carries `file`, `line`, and the file's `sha256`, so a finding can be
pointed at and re-verified after the tree moves — the property a prose audit
loses the moment anyone commits.

Refusal rule: **no row may assert intent.** `swallow_site` is an observation;
"deliberately ignoring errors" is a conclusion the reader draws.

Acceptance: on a fixture tree with one planted example of each class, every class
is found exactly once and a clean fixture yields zero rows (negative control);
running it twice on unchanged files yields identical rows apart from timestamps.

## 4. OCR intake — the document half

OCR is the only kernel here that cannot be pure stdlib: text from a scanned page
requires an engine (`tesseract`, `ocrmypdf`, `paddleocr`), and the estate has none
wired. So the kernel is **the row schema and the adapter boundary**, not the
engine:

```
{"raw", "sha", "engine", "engine_version", "page", "box", "text",
 "confidence", "lang", "fetched_at"}
```

- `box` (x0,y0,x1,y1 in page pixels) is mandatory: a claim that cannot be pointed
  at a rectangle on a page is a claim nobody can check.
- `confidence` is the engine's, labelled as such — never re-scaled into "accuracy".
- The engine is selectable and recorded; a re-run with a different engine produces
  a **new** row set, not an overwrite, so two readings can be compared.

Acceptance: a deliberately blurred page must lower confidence *and* the row must
say so; a missing engine must fail loudly with the install line rather than return
empty text (empty text is indistinguishable from a blank page).

---

## 5. `ledger` — append-only, hash-chained evidence

Kernels 2–4 all write rows that someone will later need to prove were not edited.
The estate has this idea twice (`.audit/` JSONL hash chain, DirectMemory dual
ledger) and neither is portable into an arbitrary codebase.

Kernel: append-only JSONL where each row carries `prev` (hash of the previous row)
and `self` (hash of its own canonical bytes), plus `verify(path)` that walks the
chain and reports the first break — and `anchor(path)` that emits one hash a
human can record elsewhere. A break is reported with the row number and both
hashes, never as "corrupt".

Acceptance: flipping one byte in the middle must be detected at exactly that row;
truncating the tail must be *undetectable without an anchor* and the `verify`
output must say so rather than claim integrity.

## Order of work, and what each one buys

| # | kernel | state | first evidence it is worth it |
| --- | --- | --- | --- |
| 1 | `requiem` | built, 12 codebases | a crash is answerable after the terminal closed |
| 4 | `ledger` | specified | an audit row survives a hostile edit |
| 3 | `astaudit` | specified | "how many swallow sites does this tree carry" answered without git |
| 2 | `receipt` | specified | two fetches of one URL can be compared by hash |
| 5 | `ocr` | specified | a scanned claim can be pointed at a rectangle |

The audit is kernels **3 + 4 + 5**: AST for the code, OCR for the documents, the
ledger under both. It is "investigational" only if every row is locatable and
tamper-evident; without those two properties it is a report, and reports are what
this estate keeps discovering were wrong.

## What is deliberately *not* a kernel

- **The engine** (OCR, LLM, browser). A kernel that needs a 2 GB model is a
  dependency, and dependencies are what the codebase already has to install.
- **A dashboard.** A reader with no internet and no server should still be able to
  answer "what died and where" from `requiem.jsonl` and `grep`.
- **A verdict.** Every kernel above emits observations; acceptance is the user's,
  never the tool's.
