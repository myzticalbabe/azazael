## Changes Made

### 1. Fixed 52 Broken _314t.bat Files

**Root Cause:** Every `_314t.bat` file contained `"C:\Users\clint\azazael\src$path"` — the `$path` was a template variable that was never substituted during the build process. These BATs were non-functional.

**Fix:** Created `regenerate_bats.py` in the standalone directory:
- Regenerates all `_314t.bat` files with correct pattern: `"%~dp0NAME_314t.exe" %*`
- Deletes orphaned BATs (16 modules with no matching EXE)
- Creates missing BATs for EXEs that lack launchers
- Supports `--dry-run` for preview
- **Result:** 37 correct BATs, 16 deleted, 0 broken

### 2. Fixed POPUP_Immersive_314t.exe (ImportError)

**Root Cause:** `from tkinter import webview` — `tkinter.webview` is not a standard tkinter submodule. The import always fails.

**Fix:** in `src/CODEX/POPUPS/POPUP_IMMERSIVE.py`:
- Removed `from tkinter import webview`
- Added `try: import tkinterweb` with `HtmlFrame` for optional rich HTML rendering
- Fallback to pure tkinter Text widget (always available)
- Moved `close()` button and `root.mainloop()` outside the try/except so they always execute

### 3. Fixed Auto_Doc_Gen_314t.exe (KeyError: 'file')

**Root Cause:** `extract_docstrings()` returns `{"error": "Could not parse file"}` on parse failure (dict without `file` key), but `run()` called `generate_markdown(docstrings)` which accesses `docstrings['file']` — crashing with KeyError.

**Fix:** in `src/AUTO_DOC_GENERATOR.py`:
- Added `"error" in docstrings` check in `run()` before calling `generate_markdown`
- Skipped files recorded in `results["skipped"]`
- Added `encoding="utf-8"` to `write_text()` call
- **Result:** Graceful skip of unparseable files instead of crash

## Architecture Findings

### 1. Template Variable Substitution Is a Build Pipeline Gap
The `$path` in 52 BAT files is a classic template bug — a variable meant for build-time substitution that was never processed. This suggests the original build pipeline was either:
- Manual (someone forgot to run the substitution step)
- Scripted but the script had a silent failure
- Generated by an AI/LLM that output a template instead of substituted values

**Prevention:** Always validate generated files post-build. Use `grep` to find unsubstituted template variables.

### 2. Nuitka Isolates Import Errors Better Than Development
The `from tkinter import webview` bug was never caught in development because:
- The code had an `except:` (bare except) that caught everything
- In development, the module was likely available through some other package
- Nuitka's isolated bundle made the missing dependency obvious

**Lesson:** Bare `except:` clauses hide real bugs. Always use `except ImportError` or `except Exception as e: print(e)`.

### 3. Dict Key Access Without Guards Is a Common Crash Pattern
The `KeyError: 'file'` bug follows the same pattern as the `get_all_categories()` display bug from earlier sessions — accessing dict keys that may not exist without `.get()` fallbacks or `in` checks.
